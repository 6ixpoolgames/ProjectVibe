# ProjectBase: notes for Claude

Godot 4.7 hobby project (GDScript). Meant as a reusable base for many kinds of real-time 3D games, 3D only: 2D would be a separate framework. An RTS counts as real-time 3D with extra needs on top. Very early WIP: whether a feature is used in `test scene.tscn` (the main scene) is the best indicator of whether it works. <!-- Claude 2026-11-06: the owner moved the project from 4.4 to 4.7, and set the target range -->

## Requirements from the owner

1. **Sign every change.** Any code Claude adds or modifies gets a comment saying Claude wrote it, the date, and why:
   - New script: a header line at the top, e.g. `## Written by Claude (claude-opus-5-5), 2026-11-02: <purpose>`
   - Edited block: a comment on or above the change, e.g. `# Claude 2026-11-02: <what changed and why>`
   - `.tscn` / `.tres` files can't hold comments reliably (the editor strips them), so list those changes in the commit message and in the chat summary instead.
2. **The owner wants to understand the whole codebase.** Don't make changes they can't follow. After every change, explain what changed, how it fits into the rest of the system, and anything it affects elsewhere. Prefer clear and boring over clever.
3. **Comment generously, in plain language.** The owner is getting back into reading and writing GDScript, so new GDScript explains what it does and why, and explains language features as they come up. `assets/scripts/terrain/Terrain.gd` shows the level of detail, with its `GDScript note:` comments. <!-- Claude 2026-11-05: asked for by the owner -->


## Layout

- `assets/scripts/Character Pawn/`: the pawn and its components (nexus, initializer, movement controllers, AI, stats, camera arm)
- `assets/scripts/camera/`: the old player camera, 3D cursor, free-floating camera and possession toggle, plus the new camera system, below
- `assets/scripts/singletons/`: autoloads `GlobalTools`, `GlobalAICoordinator`, `ResourcePreloadManager`, `NetworkTime` (the tick driver all new gameplay runs on; test in `singletons/tests/`), `NetworkSession` (multiplayer: connecting, spawning, inputs, snapshots) <!-- Claude 2026-11-04: added NetworkTime and NetworkSession -->
- `assets/scripts/tags/`: `TagRegistry`, tag names to bits for ability categories (declared in `resources/tag_declarations.tres`; test in `tags/tests/`) <!-- Claude 2026-11-04: new folder -->
- `assets/scripts/netcode/`: `TickStateComponent` (add as a child, list properties in the inspector, get rollback), `StateEncoding`, `NetworkEntity` (add as a child to make an entity networked), `NetPackets`, `NetClock`, `NetFakeConditions` (worst-case fake network), `NetTestBench` (debug-only keys for it and the feature switches), `LagCompensation`. Tests in `netcode/tests/`: `net_selftest` runs real connections between separate processes, `net_measure` prints numbers at set pings, `net_stress` runs many clients and pawns on hills with nav, `net_profile` shows where the time goes, `net_codec_selftest` compares C++ packet encoding (`NetCodec` in `native/`, which snapshots use, with `NetPackets` as the fallback) with `NetPackets` and times both. A change to the packet format goes in both <!-- Claude 2026-11-04: new folder; multiplayer added; 2026-11-05: net_codec_selftest; snapshots now use it -->
- Sample scenes are in `assets/scenes/samples/`, with their pawn scenes. Only the main scene `test scene.tscn` and the stale `root.tscn` are left in the project root <!-- Claude 2026-11-06: moved them out of the project root -->
- `tick_pawn_sample.tscn`: sample showing a pawn hooked onto the tick driver; scripts in `assets/scripts/samples/`, pawn scene in `assets/scenes/samples/`, test in `samples/tests/`. A teaching example, not the real pawn <!-- Claude 2026-11-04: new sample -->
- `net_sample.tscn`: a small multiplayer game to play. Open it twice, Host in one and Join in the other. In a debug build, keys change the fake network and switch features live (`NetTestBench.gd`). Scripts `samples/NetSampleGame.gd` and `NetSamplePawn.gd` <!-- Claude 2026-11-04: new sample -->
- Headless tests are scenes (so autoloads load): `"C:\Git\Test 2\Godot_v4.7.2-stable_win64_console.exe" --headless --path . "res://<path>/tests/<name>_selftest.tscn"`, exit code 0 = pass. `net_selftest` takes about 8 minutes, so give it a limit of 10 or more. Two of its checks can fail by chance, on 4.4 as well as 4.7: "dilation ramp: no more missed inputs than a fixed lead" and "adaptive interpolation: and runs out of snapshots less often". Re-run with `-- --only=dilation_ramp` or `-- --only=adaptive_interpolation` before treating either as a bug. "dilation: on a steady connection it settles with inputs 1 to 2 ticks early" failed once at 3 on Windows on 2026-11-07, then passed 6 of 6 with `-- --only=dilation`, so treat it the same way <!-- Claude 2026-11-07 --> After adding a script with a new `class_name`, run `--headless --import --path .` once first. A script that fails to compile leaves a test scene running forever, so use a timeout. The project runs on Jolt. To test on Godot's own physics, temporarily add an `override.cfg` with `[physics]` and `3d/physics_engine="DEFAULT"` <!-- Claude 2026-11-04: how to run tests; 2026-11-05: Jolt is now the project's engine; 2026-11-06: Godot 4.7.2 and how long the net test takes -->
