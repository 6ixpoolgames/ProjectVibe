# ProjectBase: notes for Claude

Godot 4.7 hobby project (GDScript). Meant as a reusable base for many kinds of real-time 3D games, 3D only: 2D would be a separate framework. An RTS counts as real-time 3D with extra needs on top. Very early WIP. The main scene is `assets/scenes/samples/pawn_sample.tscn`, and each system's tests and sample are the best indicator of whether it works. <!-- Claude 2026-11-06: the owner moved the project from 4.4 to 4.7, and set the target range; 2026-11-08: the main scene was the old test scene.tscn, now in assets/legacy/ -->

## Requirements from the owner

1. **Sign every change.** Any code Claude adds or modifies gets a comment saying Claude wrote it, the date, and why:
   - New script: a header line at the top, e.g. `## Written by Claude (claude-opus-5-5), 2026-11-02: <purpose>`
   - Edited block: a comment on or above the change, e.g. `# Claude 2026-11-02: <what changed and why>`
   - `.tscn` / `.tres` files can't hold comments reliably (the editor strips them), so list those changes in the commit message and in the chat summary instead.
2. **The owner wants to understand the whole codebase.** Don't make changes they can't follow. After every change, explain what changed, how it fits into the rest of the system, and anything it affects elsewhere. Prefer clear and boring over clever.
3. **Comment generously, in plain language.** The owner is getting back into reading and writing GDScript, so new GDScript explains what it does and why, and explains language features as they come up. `assets/scripts/terrain/TerrainGenerator.gd` shows the level of detail, with its `GDScript note:` comments. <!-- Claude 2026-11-05: asked for by the owner -->
